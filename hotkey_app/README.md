
# Упрощение узбекских текстов

Fine-tuned mT5-small — упрощает сложные (юридические, официальные) узбекские тексты.

Модель: [ismailoviskandar02/uzbek-text-simplifier](https://huggingface.co/ismailoviskandar02/uzbek-text-simplifier)

## Структура папки

```
app.py

requirements.txt
```

Веса модели грузятся автоматически с Hugging Face Hub, локальная папка `model/` не нужна.

```
pip install -U -r requirements.txt
python app.py
```

## Запуск на любой ОС: `run.py`

Вместо `python app_tkinter.py` используйте:

```
python run.py
```

Это кросс-платформенный launcher — сам определяет ОС и делает нужную
подготовку перед запуском:

- **Windows**: если процесс не запущен от администратора — покажет
  диалог UAC и перезапустится с повышенными правами (нужно для
  `keyboard`-хоткеев). Если вы нажмёте "Нет" в UAC — приложение всё
  равно запустится, просто хоткей может не зарегистрироваться (и об
  этом будет явное сообщение, а не тихий сбой).
- **Linux**: не поднимает права насильно (GUI-приложения от root — плохая
  идея, ломает `$DISPLAY`), а подсказывает: если хотите использовать
  `keyboard` — `sudo -E python3 run.py`; если root не нужен — приложение
  само переключится на `pynput` через X11.
- **macOS**: подсказывает выдать приложению/терминалу разрешения
  Accessibility и Input Monitoring в системных настройках.

Также `run.py` проверяет, что все зависимости из `requirements.txt`
установлены, и предупреждает, если чего-то не хватает — но не
устанавливает их сам.


`app_tkinter.py` умеет упрощать текст без открытия главного окна:
выделите текст в любом другом приложении, нажмите хоткей (по умолчанию
`ctrl+alt+s`, настраивается через поле `hotkey_combo` в `config.json`),
и рядом с курсором появится popup с результатом упрощения — модель при
этом уже загружена в память и переиспользуется, повторная загрузка не
происходит.

Приложение при закрытии главного окна не завершается, а сворачивается в
системный трей (иконка в трее: Открыть / Настройки / Выход) — иначе
глобальный хоткей перестал бы работать вместе с процессом.

### Права доступа к системным событиям клавиатуры

Перехват глобальных хоткеев и эмуляция Ctrl+C работают на уровне ОС, а
не через Tkinter — для этого используется библиотека `keyboard`
(Windows/Linux) или `pynput` как fallback (устанавливаются по
`requirements.txt` в зависимости от платформы). Из-за этого:

- **Windows**: библиотека `keyboard` в части случаев требует запуска
  приложения **от имени администратора**, иначе регистрация хоткея или
  эмуляция Ctrl+C может тихо не сработать на уровне ОС (в этом
  приложении такая ошибка не остаётся незамеченной — при сбое
  регистрации хоткея показывается явное диалоговое окно с описанием
  причины).
- **Linux**: библиотека `keyboard` читает `/dev/input/*` напрямую и
  обычно требует запуска **от root** (`sudo python app_tkinter.py`)
  либо прав в группе `input`. Если `keyboard` недоступен/нет прав,
  приложение автоматически переключается на `pynput` (работает через
  X11, root не требуется, но нужен запущенный X-сервер).
- **macOS**: `pynput` требует выдать терминалу/приложению разрешения
  **System Settings → Privacy & Security → Accessibility** и
  **Input Monitoring**.

Если регистрация хоткея не удалась (комбинация занята другим
приложением или не хватает прав), приложение не падает и не
останавливается молча — оно показывает сообщение об ошибке и
продолжает работать в обычном режиме (упрощение текста через основное
окно остаётся доступным).

### Замер времени отклика popup

Каждое срабатывание хоткея логирует разбивку времени в консоль:

```
[hotkey timing] total=612.3ms clipboard_capture=42.1ms inference=558.7ms other_overhead=11.5ms chars_in=340
```

- `clipboard_capture` — время на эмуляцию Ctrl+C и получение текста из
  буфера обмена (системная обвязка).
- `inference` — время самого вызова `ModelRunner.simplify()` (не
  изменилось по сравнению с основным UI).
- `other_overhead` — прочие накладные расходы обвязки (переключение
  между потоками, создание popup-окна и т.п.).

Это позволяет отдельно оценить, сколько задержки добавляет новая
системная интеграция (буфер/popup) поверх неизменного времени
инференса модели — и решить, приемлема ли эта задержка для popup-UX.
