# Uzbek Text Simplifier (юридический домен)

> **готовый приложение в папке app**

> **showcase: https://project-rho-snowy-95.vercel.app**

Упрощение сложных узбекских юридических текстов (lex.uz) для обычного
читателя.

> **Изменение скоупа (по фидбеку научного руководителя):** мультидоменный
> корпус и опциональный перевод — исследовательски рискованны без
> объективной метрики упрощения для узбекского. Core сужен до одного
> домена — **law**. Вся старая информация (мультидоменный корпус,
> sports.uz, перевод NLLB-200 и т.д.) неактуальна, перенесена в `v1/`.

## Архитектура

1. Parallel-корпус: сложный ↔ простой текст, только домен `law`
2. Fine-tuning mT5-small
3. Демо: приложение на Tkinter (`app/`)

*(Перевод на ru/en убран из core, перенесён в optional/backlog)*

## Структура репозитория

- `uz_yur_parser.py` — сбор юридического корпуса (lex.uz)
- `prompts/` — инструкция для teacher-модели (v2, рабочая)
- `simplify_state.py` — resume-логика генерации parallel-пар
- `train/finetune_mt5_small.ipynb` — обучение mT5-small
- `app/` — десктоп-приложение на Tkinter
- `v1/` — устаревшая версия: мультидоменный корпус (3320 чанков,
включая wikipedia/news/sports), старые отчёты `docs/`

## Датасет

`domain_legal.csv` — **6000+ пар** (сложный текст lex.uz → упрощённый,
сгенерировано teacher-моделью по инструкции v2).

## Закрытые вопросы

- **Text-level dedup** — решено: дедуп по нормализованному тексту

## Открытые вопросы

- **Лицензирование источников** — статус спорный, права на
использование текста lex.uz для обучения/публикации модели требуют
уточнения перед публикацией
- **Human-evaluation протокол** — teacher-generated таргет не
верифицирован объективной метрикой; нужна ручная оценка по трём
осям: простота, сохранение смысла, фактические ошибки

## Обучение

- База: `google/mt5-small`, task-prefix `"simplify: "`
- Данные: `domain_legal.csv` (6000+ пар, только домен `law`)
- Оптимизатор Adafactor, LR 1e-3, 8 эпох, `fp16` выключен (mT5 даёт
NaN loss в half precision)
- Метрики на валидации (эпоха 6/8): ROUGE-L ≈ 0.28, chrF ≈ 44.7,
монотонный рост без плато

## Метрики: как читать ROUGE-L и chrF

Обе метрики автоматически сравнивают вывод модели с teacher-generated
таргетом (не с эталоном, проверенным человеком):

- **ROUGE-L (≈0.28)** — совпадение слов и их порядка (по самой длинной
общей подпоследовательности) между выводом модели и таргетом. Значение
среднее-низкое относительно типичных задач суммаризации/simplification
на английском (там обычно 0.35–0.45+), но опубликованных бенчмарков
text simplification для узбекского нет — сравнивать особо не с чем.
- **chrF (≈44.7)** — F-мера по совпадению символьных n-грамм, а не слов.
Устойчивее к морфологии, чем BLEU/ROUGE — важно для узбекского как
агглютинативного языка, где одно слово имеет много словоформ и
словесные метрики несправедливо наказывают за это.

**Ограничение:** обе метрики показывают близость к teacher-выводу, а не
качество упрощения как таковое (упрощённость, сохранение смысла,
фактическую точность). Поэтому они рассматриваются как baseline, а не
как финальное доказательство качества — необходим human-eval (см.
«Открытые вопросы»).

## Статус

**Проект полностью готов.** Скоуп сужен до `law`, модель обучена на
legal-only данных (`domain_legal.csv`, 6000+ пар), дедуп решён,
десктоп-приложение на Tkinter работает. Перед публикацией остаётся
уточнить лицензирование источников и провести human-eval (доказательная
сила текущих метрик без него ограничена).
