# Uzbek Text Simplifier

Упрощение сложных узбекских текстов (юридических, официальных, новостных)
для обычного читателя, с опциональным переводом результата на ru/en.

## Архитектура

1. Parallel-корпус (сложный ↔ простой текст)
2. Fine-tuning mT5-small
3. NLLB-200 — опциональный перевод на ru/en
4. Демо: FastAPI + Streamlit/Gradio, деплой на HuggingFace Spaces

## Структура репозитория

**Сбор данных:**
- `uz_news_parser.py`, `uz_news_parser2.py`, `uz_news_parser3.py` —
  новости (kun.uz, gazeta.uz, uza.uz) + Wikipedia, последовательные
  версии (v3 — актуальная)
- `uz_yur_parser.py` — юридический корпус (lex.uz)
- `uz_wiki_parser_1000.py`, `uz_wiki_parser_new.py` — дополнительные
  прогоны Wikipedia; статус подтверждён, результат уже включён в
  объединённый корпус
- `uz_sports_parser.py` — спортивный корпус (sports.uz); **статус
  подтверждён, включён в объединённый корпус**. Своя схема полей
  (`subcategory` вместо `domain_filled_auto`/`origin_file`) — при
  объединении недостающие столбцы восстановлены (`domain_filled_auto=False`,
  `origin_file` проставлен на имя исходного файла), `subcategory`
  добавлен как пустой в основной части корпуса

**`docs/`** — отчёты и документация корпуса:
- `corpus_fields.md` — формулы и описание всех полей датасета
- `merge_report.md` — объединение прогонов в финальный корпус
  (обновлено: включает мердж спортивного корпуса и дедуп по
  `url`+`chunk_id`)
- `cleaning_report.md` — отчёт по очистке текста от мусора разметки

**`prompts/`** *(рекомендуется завести)* — инструкции для teacher-модели,
генерирующей parallel-пары:
- инструкция v1 — консервативная (сохранить 85–95% информации)
- инструкция v2 — агрессивная (сократить на 40–60%)
- **инструкция v3 — актуальная**, доработка v2 под текущий состав
  корпуса: числа/статистика сохраняются, если они и есть главная новость
  (счёт матча, число жертв ДТП и т.п.), уточнён критерий "central
  person", для юридических текстов требование не выхолащивать суть
  регулирования, для коротких текстов (<~80 слов) снята жёсткая
  привязка к 40–60%, добавлены 3 эталонных примера "до/после"

**Статус выбора версии: v3 выбрана как рабочая.**

## Датасет

CSV-схема: `source, title, url, chunk_id, text, word_count, length,
avg_sentence_len, avg_word_len, rare_word_ratio, complexity_score,
domain, domain_filled_auto, origin_file, subcategory`

Файл: **`uz_corpus_combined.csv`** (объединяет
`uz_corpus_merged_final_fixed.csv` + `uz_corpus_sports_20260723_1838.csv`).

После объединения и дедупа по `url`+`chunk_id`: **3320 чанков**,
~363 000 слов (удалено 28 почти-дублей — один и тот же чанк из разных
прогонов парсера с разной степенью очистки разметки; в каждой паре
оставлена версия с меньшим числом артефактов вида `[1]`,
`{\displaystyle...}`, HTML-тегов).

⚠️ Дедуп на этом шаге сделан по `url+chunk_id`, а не по тексту чанка —
не ловит случаи, когда один и тот же текст получил разный `chunk_id` в
разных прогонах. Перед генерацией parallel-пар рекомендуется
дополнительный дедуп по точному/нормализованному тексту.

| source | строк |
|---|---|
| wikipedia | 1121 |
| lex.uz | 1071 |
| sports.uz | 776 |
| gazeta.uz | 124 |

Домены: law ~38%, sport ~28%, science ~9%, economy ~5%, culture ~5%,
остальное (politics/technology/health/other/education) — по убыванию,
каждый <5%. Подробности — в `docs/merge_report.md`.
