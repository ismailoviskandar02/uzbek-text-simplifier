# Uzbek Text Simplifier — сводка проекта

Капстоун-проект: сервис, упрощающий сложные узбекские тексты (юридические
документы, официальные новости, гос. инструкции) для обычного читателя,
с опциональным переводом результата на русский/английский.

## Идея

Выбор пал на **NLP для узбекского языка** — нишу почти без готовых
инструментов (в отличие от английского). Из вариантов (классификация
новостей / тональность / NER / упрощение текста) выбрано **text
simplification** — сильнее по бизнес-ценности и без готовых конкурентов
под узбекский.

**Архитектура:**
1. Сбор parallel-корпуса (сложный ↔ простой текст)
2. Fine-tuning mT5-small на корпусе
3. NLLB-200 — опциональный перевод упрощённого текста на ru/en
4. Демо на FastAPI + Streamlit/Gradio, деплой на HuggingFace Spaces

## Сбор корпуса

Основные источники собраны серией парсеров с единой CSV-схемой (source,
title, url, chunk_id, text, word_count, length, avg_sentence_len,
avg_word_len, rare_word_ratio, complexity_score, domain). Чанкинг —
100–200 слов по границам предложений.

- Новости: kun.uz, gazeta.uz, uza.uz (RSS)
- Wikipedia: 14 категорий, рекурсивный обход подкатегорий (до 2 уровней)
- lex.uz: юридический корпус, 9 документов (ручной seed-список) — самый
  "сложный" стилистический полюс
- **sports.uz**: отдельный прогон парсера (776 строк) — добавлен позже
  как отдельный домен `sport`, схема почти идентична основной, но вместо
  `domain_filled_auto`/`origin_file` был столбец `subcategory` (football
  и др.) — при объединении недостающие столбцы были восстановлены
  (`domain_filled_auto=False`, `origin_file` проставлен), `subcategory`
  добавлен как пустой в основной корпус для сохранения совместимости

Сложность текста считается тремя эвристиками (без готовых NLP-инструментов
под узбекский): средняя длина предложения, доля редких слов, средняя длина
слова → взвешенный `complexity_score`.

## Объединение и очистка

Было собрано несколько дополнительных прогонов парсера поверх основного
датасета, включая отдельный прогон sports.uz. Итоговое объединение всех
файлов и дедуп дали:

- **Итог: 3320 строк**, ~363 000 слов
- Дедуп на этом шаге делался по `url` + `chunk_id` (а не по тексту чанка) —
  найдено 28 почти-дублей: один и тот же чанк попадал из разных прогонов
  парсера с разной степенью очистки разметки (в одной версии оставались
  артефакты `[1]`, `{\displaystyle...}`, HTML-теги вроде `<i>`/`</link>`,
  в другой — уже вычищены). Для каждой пары оставлена версия с меньшим
  числом артефактов (эвристика по количеству `[N]`, `{\displaystyle`,
  html-тегов и обратных слэшей)
  - ⚠️ Важно: дедуп по `url+chunk_id` не ловит дубли, где один и тот же
    текст получил *разный* `chunk_id` в разных прогонах (такое было
    описано в предыдущей версии сводки при объединении 2033-строчного
    датасета через дедуп по тексту). Стоит на финальном шаге прогнать
    ещё и дедуп по `text` (точное совпадение) и, желательно, по
    нормализованному тексту (без разметки/пунктуации) — за счёт
    sports.uz и других прогонов не исключено появление новых текстовых
    дублей, которые не совпадают по `url+chunk_id`
- Источники: wikipedia 1121, lex.uz 1071, **sports.uz 776**, gazeta.uz 124,
  uza.uz 124, kun.uz 104
- Домены: law 1276 (38%), **sport 935 (28%)**, science 287, economy 181,
  culture 175, politics 116, technology 96, health 96, other 82,
  education 76
- Добавление sports.uz заметно выправило перекос на law (было 59%,
  стало 38%), но появился новый крупный домен sport (28%) — для
  fine-tuning всё ещё стоит следить за health/technology/education/other
  (<100 строк каждый)

Отдельно, ещё на этапе сбора 2033 строк, была очистка мусора разметки
(LaTeX-дампы, HTML-теги, обрывки твит-виджетов, zero-width символы):
изменено 45 строк из 2033, пустых строк после чистки не возникло. Часть
такой разметки, тем не менее, всплыла позже как раз в найденных
почти-дублях (см. выше) — то есть чистка на предыдущем этапе была
неполной для части файлов.

## Инструкции для teacher-модели (генерация parallel-пар)

Найдено две версии инструкций для упрощения текста, задающие **разные
стратегии**:
- **v1** — консервативная: сохранить 85–95% исходной информации, не
  сокращать по объёму
- **v2** — агрессивная: сократить длину на 40–60%, разрешено убирать
  даты, номера статей закона, статистику ради простоты

Это не разные формулировки одного и того же, а разный подход к задаче.
Нужно явно выбрать одну версию перед генерацией parallel-пар — иначе
датасет получится методологически неоднородным (часть пар "почти
дословный пересказ", часть — "сжатый пересказ").

**Статус: выбрана v2, доработана до v3.** Правки внесены под текущий
состав корпуса (юридические тексты + новости + добавленный домен sport):

- уточнено, что числа/статистика в текстах, где они и есть главная
  новость (счёт матча, число жертв ДТП, рекорды), должны сохраняться —
  правило "MAY remove statistics" изначально было слишком общим и грозило
  выхолащиванием именно спортивных и новостных чанков (совокупно теперь
  ~35% корпуса)
- уточнён критерий "central person" (упомянут в заголовке/несколько раз)
- для юридических текстов (38% корпуса) добавлено явное требование не
  сжимать до одной обтекаемой фразы, а сохранять суть регулирования
- для коротких текстов (<~80 слов — таких много среди sports.uz чанков)
  снята жёсткая привязка к 40–60%, приоритет — естественность
- добавлены 3 эталонных примера "до/после" (новость со статистикой,
  юридический фрагмент, короткий спортивный текст) для стабильности
  формата при генерации

## Проверка качества

Прогнан через DataStory (Tkinter + Gemini) и ручной аудит. Автоматические
"тревоги" AI-анализа (уникальность `text`, "выбросы" в длине чанков,
будущие даты 2026) — ложные срабатывания, ожидаемые для NLP-датасета.
Ручной аудит дополнительно выявил утечку разметки (LaTeX/HTML/твиттер),
не пойманную парсером и DataStory — исправлено.

**Открытый вопрос перед генерацией parallel-корпуса:** прогнать
дополнительный дедуп по тексту (см. выше) поверх текущих 3320 строк,
прежде чем запускать teacher-модель по инструкции v3 — иначе есть риск
сгенерировать дублирующиеся parallel-пары из почти-идентичных чанков.
